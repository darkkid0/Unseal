# Technology Stack

**Analysis Date:** 2026-07-13

## Languages

**Primary:**
- Swift 6.2 language/tooling baseline - All application and test code under `Sources/AppModule/`, `Sources/UnsealCore/`, `Tests/AppModuleTests/`, and `Tests/UnsealCoreTests/`; the package declares `swift-tools-version: 6.2` in `Package.swift`.

**Secondary:**
- Bash (version not pinned) - Native build, universal-app packaging, signing, notarization, and icon generation in `package_app.sh` and `generate_app_icon.sh`.

## Runtime

**Environment:**
- Native macOS application targeting macOS 13 or newer - Declared with `.macOS(.v13)` in `Package.swift` and `LSMinimumSystemVersion` in the `Info.plist` generated by `package_app.sh`.
- Apple Swift 6.2 toolchain - The repository documents Xcode 26 / Swift 6.2 in `README.md`; the analyzed machine provides Apple Swift 6.2.4 and Xcode 26.3.
- Menu-bar accessory process - `Sources/AppModule/AppDelegate.swift` applies the `.accessory` activation policy, and `package_app.sh` emits `LSUIElement=true` so the installed app runs without a Dock icon.

**Package Manager:**
- Swift Package Manager from the Swift 6.2 toolchain - Product and target declarations live in `Package.swift`; normal development uses `swift run`, `swift build`, and `swift test` as documented in `README.md`.
- Lockfile: `Package.resolved` is absent because `Package.swift` declares no remote package dependencies.

## Frameworks

**Core:**
- SwiftUI (macOS 13 SDK or newer) - App lifecycle, settings scene, popover content, drag-and-drop UI, and diagnostics in `Sources/AppModule/UnsealApp.swift`, `Sources/AppModule/SettingsView.swift`, `Sources/AppModule/MenuContent.swift`, and `Sources/AppModule/DropZoneView.swift`.
- AppKit (macOS 13 SDK or newer) - `NSApplicationDelegate`, accessory activation, `NSStatusItem`, `NSPopover`, context menus, and SwiftUI hosting in `Sources/AppModule/AppDelegate.swift` and `Sources/AppModule/StatusItemController.swift`.
- Combine (macOS 13 SDK or newer) - Observes published app/login-item state to resize the popover in `Sources/AppModule/StatusItemController.swift`.
- Foundation and Darwin (Swift 6.2 SDK) - Filesystem access, subprocess execution, dispatch queues, temporary output capture, POSIX signals, property lists, and preferences in `Sources/UnsealCore/QuarantineService.swift`, `Sources/AppModule/AppModel.swift`, and `Sources/AppModule/LaunchAtLoginController.swift`.
- ServiceManagement (macOS 13 SDK or newer) - Main-app login-item registration and System Settings integration through `SMAppService` in `Sources/AppModule/LaunchAtLoginController.swift`.

**Testing:**
- XCTest bundled with Xcode 26 - Unit and state-transition tests in `Tests/UnsealCoreTests/QuarantineServiceTests.swift`, `Tests/AppModuleTests/AppModelTests.swift`, and `Tests/AppModuleTests/LaunchAtLoginControllerTests.swift`.
- SwiftPM test runner - `UnsealCoreTests` and `AppModuleTests` are declared as test targets in `Package.swift` and run with `swift test` from `README.md`.

**Build/Dev:**
- SwiftPM 6.2 - Builds the `Unseal` executable product from the `AppModule` target and local `UnsealCore` library target in `Package.swift`.
- Xcode Command Line Tools - `package_app.sh` uses `lipo`, `codesign`, `plutil`, `ditto`, and `xcrun`; `generate_app_icon.sh` uses `sips` and `iconutil`.
- Universal binary packaging - `package_app.sh` builds `arm64` and `x86_64` release binaries, merges them with `lipo`, and creates `.build/release/Unseal.app`.

## Key Dependencies

**Critical:**
- No third-party libraries - `Package.swift` contains only local target dependencies, so additions should prefer Apple SDK APIs unless a new package is deliberately introduced.
- `UnsealCore` local target - Owns command execution, quarantine removal, Gatekeeper assessment, and diagnostic models in `Sources/UnsealCore/QuarantineService.swift` and `Sources/UnsealCore/Diagnostics.swift`; `AppModule` depends on it in `Package.swift`.
- `/usr/bin/xattr` and `/usr/sbin/spctl` - Runtime security tools invoked by `Sources/UnsealCore/QuarantineService.swift` to inspect/remove only `com.apple.quarantine` and reassess the selected app with Gatekeeper.
- ServiceManagement `SMAppService` - Preferred login-item mechanism in `Sources/AppModule/LaunchAtLoginController.swift`, with a user-level LaunchAgent fallback for incomplete/ad-hoc app-service registration.

**Infrastructure:**
- macOS filesystem and process APIs - `FileManager`, `Process`, `FileHandle`, `DispatchQueue`, `DispatchSemaphore`, and Darwin signals implement bounded subprocess execution in `Sources/UnsealCore/QuarantineService.swift`.
- macOS signing/notarization tools - `package_app.sh` performs ad-hoc or Developer ID signing and optionally submits the packaged app through `xcrun notarytool` before stapling it.

## Configuration

**Environment:**
- Application runtime requires no environment variables; application preferences use `UserDefaults` under `LaunchAtLoginEnabled` in `Sources/AppModule/LaunchAtLoginController.swift`.
- Packaging accepts `BUNDLE_IDENTIFIER`, `MARKETING_VERSION`, `BUILD_NUMBER`, `SIGNING_IDENTITY`, and `NOTARYTOOL_PROFILE` in `package_app.sh`; defaults are provided except for signing identity and notarization profile.
- A local `.env` file is present, but its contents were not inspected and neither `Sources/` nor `package_app.sh` automatically loads it.

**Build:**
- `Package.swift` - Swift tools version, macOS deployment target, executable/library/test targets, and local target dependency graph.
- `package_app.sh` - Release build, dual-architecture merge, generated app metadata, icon embedding, code signing, optional notarization, and `.build/release/Unseal.app` output.
- `generate_app_icon.sh` - Converts source PNGs from `icon/` into `Sources/AppModule/Resources/AppIcon.icns`; `Package.swift` excludes `Resources/` from compilation and `package_app.sh` copies the icon into the app bundle.
- `.swiftpm/xcode/package.xcworkspace/contents.xcworkspacedata` - Generated SwiftPM/Xcode workspace metadata; there is no checked-in `.xcodeproj` or custom `.xcconfig`.

## Platform Requirements

**Development:**
- macOS 13 or newer with Xcode 26 / Swift 6.2 and Xcode Command Line Tools, as specified in `README.md`, `Package.swift`, `package_app.sh`, and `generate_app_icon.sh`.
- Run `swift run` for development, but use the complete `.app` from `package_app.sh` when validating login-at-launch behavior, as documented in `README.md`.
- Universal packaging is designed for Apple Silicon; the `x86_64` cross-build requires Rosetta, and `README.md` notes that Intel hosts cannot produce the scripted `arm64` build.

**Production:**
- Locally installed native `.app` bundle, normally copied from `.build/release/Unseal.app` to `/Applications/` according to `README.md`; there is no server or browser runtime.
- `arm64` and `x86_64` universal executable with minimum macOS 13, assembled by `package_app.sh`.
- Ad-hoc signing is the default for local use; public distribution requires a Developer ID identity and may use Apple notarization through the optional settings in `package_app.sh`.
